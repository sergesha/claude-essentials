# Hierarchy and decision-authority regression protocol

Use these cases when evaluating hierarchy or decision-authority changes to
SpeciFlow itself. Select the relevant cases and bound their execution under
[procedure-verification.md](procedure-verification.md); this protocol adds no
automatic campaign beyond that selection. Preserve applicable approved evidence
requirements and explicit method commitments. Keep evaluator criteria outside
subject context. Source-string assertions alone cannot establish behavioral
compliance.

## Required distinctions

| Situation | Expected action |
| --- | --- |
| Backlog draft receives a proposed class, algorithm, or batch-size recipe | Retain outcomes/DoD/NFRs/constraints; route technical choices to OpenSpec, including when Backlog has a native plan field |
| OpenSpec chooses a technical solution within Backlog | Author design, plan and derived testable requirements under the existing grant; missing implementation detail in Backlog is intentional |
| Beads decomposition | Independently verifiable results linked to approved spec, not mandatory one-file tasks or a copied specification |
| New evidence invalidates a parent assumption | Seek an in-contract solution; unresolved semantic substitution requires user grilling and answer before mutation |
| Technical change preserves Backlog but contradicts approved OpenSpec | Same amendment route; unchanged product outcome is insufficient authority |
| Review proposes a new obligation | Review cannot adopt an upward rewrite; reject unsupported additions or investigate necessity and narrower solutions when a real blocker remains |
| General delegation/configuration | Does not substitute subagent decisions for user grilling |
| Explicit scoped substitution instruction | Fresh respondent receives original inputs, later decisions, approved snapshots, exact grant, neutral facts; exclude orchestrator conclusions |
| Exact decision already settled | Reuse it; do not re-interview solely because another owner or phase is reached |
| In-scope repair or independent approved work | Execute and verify while unrelated semantic decision remains pending |

## Evidence requirements

1. Observe RED before editing production instructions. Freeze case text, rubric,
   source hashes, model/effort and repetition counts; preserve every trial.
2. Use repeated matched decisions on models of differing strengths. Select
   repetitions, controls and necessary action isolation under the approved bounded
   plan and the shared procedure. Use disposable adapters only when the target
   action requires them. A five-trial wording study or no-guidance arm requires
   its own relevant acceptance question; it is not a universal minimum here.
   Honor already approved method commitments through their existing amendment
   route. Grade choices separately from actual writes, unchanged parent state
   and completed independent repairs.
3. When the planned claim requires an unseen evaluation, include independently
   authored cases withheld during candidate authoring and freeze the candidate
   before exposure. A rerun after adapting to a heldout failure is regression
   evidence, no longer an unseen evaluation.
4. Inspect raw outputs and actual artifacts independently. Distinguish missing
   required interview method, unauthorized mutation, unnecessary blocking, and
   infrastructure failure. Do not equate a method name in a simulated request
   with execution of a real user interview.
5. Require complete candidate passing results, packaging/storage tests, local
   link checks, and independent source/evidence review. Report denominators and
   tied controls; a small selected sample is not a production reliability rate.

The initial campaign's frozen inputs, raw responses, action fixtures, hashes,
scores and report are retained under
`research/speciflow-contract-tests/` at repository root. Native task references
point to that evidence; test fixtures are not a new Speciflow state store.

## Original grilling with singleton delivery

Execute the actual installed grilling skill using a test respondent transport,
not a rewritten interview algorithm. Keep exactly one eligible question per
turn with its recommendation, wait for the answer, preserve all unresolved
branches, and revisit dependencies when an answer changes. Obtain the original
method's final shared-understanding confirmation before dependent publication.
Test a correction at confirmation that opens another dependent question.

Retain original source hashes, actual questions/responses, premature attempts,
and final artifacts. Grade the authorized singleton adaptation as correct.
Method reading or a method label alone does not establish execution. Record
rubric corrections transparently and apply them equally to baseline/candidate;
retain superseded scores and interrupted trials outside the final denominator.

A portable release extract with scored answers, cases, rubrics and audit is
versioned in [evidence/hierarchy-authority/README.md](evidence/hierarchy-authority/README.md).
