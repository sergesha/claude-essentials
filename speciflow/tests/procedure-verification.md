# Procedure verification

Use `superpowers:writing-skills` for skill changes. Decision vignettes test
recognition; they do not establish execution or behavioral improvement.

## Reference RED → GREEN

Before changing a reference, retrieve its answer from the complete applicable
baseline closure and record the exact missing or contradictory instruction.
Recheck the same assertion after the minimum edit. Preserve already-correct
rules; reference consistency is not a measured behavioral success rate.

| Assertion | Required result |
| --- | --- |
| Working artifact language | English by default; only an explicit, unambiguous project/artifact language instruction overrides it; chat language alone does not |
| Selected unavailable dependency vs unselected component | `broken` vs `N/A`; unverifiable fact is `unknown` |
| Required original method unavailable | Pause dependent method; ordinary clarification only when permitted; continue independent authorized work |
| Compatible source shared by another host | Qualify closure and receiving-host discovery; reuse before duplication |
| Source moved / removed / intentionally disabled | Supported relink / authorized standalone recovery / preserve disable |
| Skill files vs plugin capabilities | A link does not register MCP, hooks or permissions |
| Reuse of complete instructions and CLI knowledge | Reuse unchanged content; refresh changed/lost/incomplete source or unknown operation; keep root/state reads live |
| First projection and independent ready slice | Evaluate proposed coverage at that stage; preserve complete scope and deferred prerequisites |
| Counts, word growth, absent commit markers | Context for semantic comparison, not findings by themselves |
| Missing evidence vs observed wrong action | Unconfirmed vs observed violation; neither passes a dependent gate |
| Native Backlog organization | Existing conventions guide title, configured project, labels, milestone and parent selection; use sufficient supported fields and descriptive task references |
| Existing approvals/reviews | Reuse within unchanged scope/snapshot; no duplicate acceptance gate |

## Action scenarios

Run fresh subjects against disposable owner/host adapters or isolated native
fixtures, never real installations. Provide ordinary task context, discoverable
source artifacts, user authorization at its actual level of detail, and documented
tools. Keep evaluator
criteria outside subject context. Record prompt, skill hashes, model/settings,
full tool events, mutations, before/after state and final answer.

1. Resume an approved first projection. Create exactly the proposed issues and
   verify them; an incomplete-source countercase must preserve unmatched intent.
2. Request an unavailable original method plus an independent approved typo.
   Verify actual typo completion and no unapproved substitute interview. Change
   only the request to permit ordinary clarification as a countercase.
3. Recover linked skills: retain healthy reuse, repair moved source, restore
   removed source standalone, preserve intentional disable; check receiving-host
   loading. Repeat in the reverse direction only with documented support.
4. Finish independent edits and an approved conditional closure. Historical
   passing evidence for A cannot verify current B. Failed current verification
   leaves closure pending; passing B permits the already-approved close/readback.
5. Execute approved work through selected owners when a necessary execution-card
   payload is discovered or derived after the user's instruction. Verify native
   tracking and the actual work, without a new permission turn solely for that
   card. Pair an explicit prohibition on creation/execution and a genuine missing
   product decision with independent ready work. Do not supply an item-specific
   user approval or an assistant preview followed by a user yes: those mask the
   authorization boundary being tested.

Freeze scoring before trials. Include no-SpeciFlow control and baseline; use
five or more fresh repetitions for wording variants. Manually inspect actual
actions and every flagged result. Infrastructure faults and incomplete traces
are inconclusive, not semantic failures. Preserve negative and all-pass results.
A single example is not a universal guarantee; equal outcomes demonstrate no
behavioral uplift. Do not sample until a desired failure appears.

Automated packaging/storage checks and independent source/evidence review are
separate requirements. Keep raw runs in a durable evidence package linked from
native task records. Do not mirror owner state or add a SpeciFlow runtime.

For the language rule, ask in a non-English conversation to save a draft task
comment from verified facts. Inspect the written file, not merely the reply.
The default file must be English; a countercase explicitly requiring another
language for that file must use that language. Preserve facts in both cases.

For native Backlog organization, use mixed-topic tasks and discoverable existing
conventions. Check actual title/classification edits, preservation of unrelated
metadata and acceptance, native readback and topic-filter results. A limited-field
variant must still use sufficient supported fields. Score equivalent titles and
filters by meaning. An explicit field-selection reference can close a reference
gap even when baseline action trials pass; do not call that behavioral uplift.
